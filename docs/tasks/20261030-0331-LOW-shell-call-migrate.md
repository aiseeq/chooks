## Что сделать
Постановка уточнена по ревью этапа 1 и выпускам akit v1.11.0–v1.12.1 (журнал ниже). Общее правило: ошибка `shellcmd` означает, что вызова нет — пакет отвергает только то, что отвергает и `bash -n`. `*shellcmd.NestedError` (битый вложенный скрипт) — внешние вызовы в деле. Своих обходов разбора (Trim кавычек, запасной `parseShell`, регулярки) нет.

1. unsentcheck (`internal/unsentcheck/check.go`): `chatCall` — через `shellcmd.Find(command, "reddy")`. Вызов есть, если у какого-то Call первый аргумент, не начинающийся с `-`, равен `history`. Регулярки убраны. Поле `ParseErrors` не заводится (снято на ревью).
2. corpus_sweep (`internal/tools/corpus_sweep.go`): поиск — по `shellcmd.Calls` (имя из `corpusSearchTools` у любого Call). Слова корпуса — `Args` всех Call плюс слова `parseShell` (присваивания, `for … in`, `cd`). Ошибка разбора — не блокировать, текст ошибки — в `ParseError`.
3. pgrep_ancestors (`internal/tools/pgrep_ancestors.go`): позиция вставки -A — по `Call.Offset`, у скрипта `bash -c` — по карте позиций значения в кавычках (`scriptSource`). При `NestedError` хук (`cmd/chooks/pgrep.go`) применяет подмену и пишет Warn.
4. Тесты: старые ожидания не менялись (сигнатура `RewritePgrepAncestors` стала тройкой с error); новые — 4 пропуска сухого прогона corpus_sweep (Blocked), `bash -c 'reddy history chat'` и `graft exec -- reddy history chat` — вызов, экранированный `bash -c "…"` и `pgrep -P` для pgrep, NestedError во всех трёх.
5. Сверка на трёх корпусах (см. «Приёмка»): каждое расхождение разобрано.
